# Windows 版 GUI 確認手順書（scripts/project-bridge-gui.ps1）

この手順書は、Windows 版の管理画面を **実機で順に確かめる** ためのチェックリストです。

- 作成した PC（Ubuntu）には pwsh も Windows も無く、`project-bridge-gui.ps1` は **一度も実行していません**。
- 作成した PC で確かめたのは、静的試験 `python3 scripts/gui-selftest-windows-static.py` の範囲だけです。
  内容は、ソースの書き方・括弧の対応・禁止語と書き込み命令・説明データと CLI の整合・引用関数と表示の無害化・承認ダイアログの中身を作る関数のアルゴリズム（Python へ写した版）です。
- 画面の表示、マウスオーバーの説明、子プロセスの出力の流れ、承認ダイアログの読了の確認、別コンソールでのキー入力は、この手順書で確かめます。
- 2026-10-08〜09 の修正（Windows 11・PowerShell 7.6.6 で作業）では、構文解析、画面を表示しないメモリ上の確認、静的試験（22 項目）、「起動してウィンドウが出たら閉じる」だけの確認を行いました（修正前は StrictMode の例外でウィンドウが出ずに終了コード 1、修正後は「ChatGPT Project Bridge 管理画面」が出て終了コード 0）。この手順書の各項目（画面の操作と見え方）は実施していません。
- 2026-10-09 の追加（ハブの稼働表示と、分かっている値の自動入力。Windows 11・PowerShell 7.6.6 で作業）では、構文解析（エラー 0 件）、静的試験（24 項目）、にせの `%APPDATA%` の中での関数の試験、**主画面を表示しない**確認を行いました。表示しない確認は、`Start-BridgeGui` の `ShowDialog` だけを「ハンドルの作成・`Shown`・メッセージの処理・`FormClosed`」に差し替えて実行し、`DrawToBitmap` の PNG を見たものです。主画面を実際に表示しての確認（B-1〜B-20）は実施していません（内訳は「既知の未検証点」の 20〜24 と「2026-10-09 に確かめたこと」）。

## 記入のしかた

- 各表の「合否」欄に `○`（期待どおり）、`×`（違う）、`－`（実施しない）を書きます。
- `×` のときは、画面下部の「コピー」ボタンでログ欄の全文を取り、項目番号と一緒に残します。
- 「期待する表示」の行番号（例: `ps1:642`）は、作成時点の `project-bridge-gui.ps1` の行番号です。

## 承認ダイアログ

承認ダイアログは、上から次の順に並びます（`ps1:2515` Show-ApprovalDialog）。

1. **固定の見出し**（スクロールしない）: 「承認状態: …」（太字）、「プロジェクトルート: "…"」、「プロファイル（承認の保存先の名前）: "…"」、ハブ方式なら赤字の警告。値は二重引用符で囲み、制御文字・行区切り・双方向制御文字・U+0020 以外の空白は `\uXXXX` で示します（共通仕様 S2）。
2. **詳細の一覧**（ListBox。1 行 1 項目でスクロールする。省略しない）: 承認できない項目（あれば）、形式が想定と違う欄（あれば）、前回の承認から変わった項目（変更ありのとき）、【対象】、【公開ファイル】、【公開ディレクトリ（Markdown だけ）】、【拒否ディレクトリ】、【その他の項目】（あれば）、【Git と文書の上限】、【公開範囲の指紋（SHA-256）】、最後の行「（一覧はここまでです）」。各項目に番号が付きます。
3. **一覧の下の固定部分**（スクロールしない）: 承認できない理由（赤字・太字）、別フォルダーの上書きの警告と追加のチェック（必要なときだけ）、要約 4 行（件数、Git のファイル名 / コミット件名、文書 1 件の上限、指紋 64 桁）、「内容を読みました」と案内、ボタン（右に「キャンセル」、その左に「この内容で承認」）。

ダイアログは画面の作業領域に収まる大きさで開き、最大化できます。大きさを変えると、見出しと要約の文の折り返し幅とボタンの並びの幅を合わせ直します（狭くしても右端のボタンが切れない。`ps1:2479`）。

## 既知の未検証点

### この PC で確認できなかったこと

作成した PC には pwsh も Windows も無いため、次はコードを読んだうえでの見込みです。危険度の高い順に並べます。行番号は `project-bridge-gui.ps1`（`ps1:`）と `project-bridge.ps1`（`cli:`）です。

1. **スクリプト全体が一度も解析・実行されていない。** 括弧の対応・禁止語・規約・純粋関数の規則（Python へ写した版との突き合わせ）は静的試験で見ましたが、PowerShell の構文解析器は通していません。S-0・S-1 で赤いエラーが出たら、その行番号を記録してください。
2. **承認ダイアログの読了の確認**（`ps1:2495` Update-ApprovalReadGate、`ps1:1019` Test-ListScrolledToEnd）。ListBox の `TopIndex`・`ClientSize.Height`・`ItemHeight` から「TopIndex + 切り捨て(ClientSize.Height ÷ ItemHeight) ≥ 行数」で末尾までの表示を判定し、150ms の Timer（`ps1:2538`）とダイアログの `Shown` で調べています。`IntegralHeight = $false` で最後の行が一部だけ見える場合、表示倍率で `ItemHeight` が実際の行の高さと違う場合、横のスクロールバーが出て `ClientSize` が変わる場合に、末尾まで動かしても押せるようにならない（または早すぎる）おそれがあります（A-4・A-5・A-7）。押せないままなら、ダイアログを広げる・最大化しても変わらないかを記録してください。`SelectionMode = None` の ListBox で、ホイールとスクロールバーは動く見込みですが、キーボード（PageDown など）で動くかは未確認です。
3. **別コンソールの補助役**（`ps1:2017` Start-KeyConsole → `ps1:3416` Invoke-ConsoleHelper・`ps1:3397` Wait-ConsoleEnter）。`pwsh -File <GUI> -ConsoleHelper -Action … -ProjectRoot …` の引数が GUI の `param`（`PositionalBinding = $false`）へ正しく結び付くこと、`& <CLI> @引数 | Out-Host` で CLI の `Read-Host`（`cli:943` のキー、Tunnel ID）が普通に入力を待つこと、`[Console]::KeyAvailable` と `[Console]::ReadKey($true)`（表示しない）で溜まった入力を捨ててから Enter を待つこと、`exit` で終了コードが返ることは未確認です（K-1〜K-16）。補助役は、CLI が `exit` で 0 以外を返したときだけ、その終了コードを返します（CLI を呼ぶ前に `$LASTEXITCODE` を 0 にし、呼んだ後の `$?` が偽のときに `$LASTEXITCODE` を使う）。CLI が正常に終われば 0、例外で止まれば 1、引数が不正なら 2 です。CLI が途中で呼んで失敗として扱わなかった外部コマンドの終了コードは使いません（`pwsh -File` で起動したときと同じ結果。CLI も正常に終わると最後に `$LASTEXITCODE` を 0 に戻す）。2026-10-09 に、にせの CLI 4 種（正常・`exit 3`・例外・外部コマンドが 5 を返したあと正常）で 0・3・1・0 を確かめました。
4. **別コンソールの子の見張り**（`Start-Process -PassThru` の `HasExited`・`ExitCode`、`ps1:1705` Update-ConsoleState）。主画面の Timer（`ps1:3336`）で 150ms ごとに調べます。承認ダイアログなどのモーダルを開いている間は調べません（`InTick`）。終わったのにボタンが戻らない場合は、ログの「別のコンソール窓が閉じました」の有無を記録してください（K-5・K-10）。
5. **Timer で子プロセスの出力を読む流れ**（`ps1:1585` Start-CliJob、`ps1:1629` Read-CliJobOutput、`ps1:1655` Update-CliJobState）。`StreamReader.ReadLineAsync()` の Task を保持し、UI スレッドの Timer で `IsCompleted` と `Result` を見ています。.NET のイベント（OutputDataReceived）は使っていません。Timer の処理の中で承認ダイアログ（モーダル）を開くため、処理中の再入を `InTick` で止めています（`ps1:1657`）。承認ダイアログの中の Timer は別の部品です。出力が途中で止まる・二重に出る・最後の数行が欠ける、のどれかが起きないかを E-6・E-8・H-1 で見てください。
6. **承認ダイアログの配置**（`ps1:2515` Show-ApprovalDialog）。見出しと一覧の下の固定部分は、`AutoSize` の `FlowLayoutPanel` を `Dock = Top / Bottom` にしています（高さは中身から決まる見込み）。ラベルは `MaximumSize` の幅（ダイアログの中の幅から 40 を引いた幅。既定の大きさで 840。大きさを変えると合わせ直す。`ps1:2479`）で折り返します。表示する前に、親の画面がある画面の作業領域に収まるよう大きさを縮め（`ps1:1523`）、最大化を許します。長いパス（空白の無いもの）が見出しで折り返されずに切れる場合は、一覧の【対象】の行（横スクロールで全体が見える）で確かめられます。表示倍率によっては一覧の高さが小さくなりすぎることがあります（A-8）。
