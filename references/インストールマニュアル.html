検証 3. 実行前の照合（必須）

インストーラーは自分自身の改ざんを検知できません。コピーしたフォルダーは、実行する前に人が照合します。

別経路で受け取るもの：署名者の公開鍵を書いた allowed_signers（初回だけ）と、各OSの SHA256SUMS.txt の指紋（ExportBundle が最後に表示するSHA-256）。Bundleと同じUSBや共有フォルダーで受け取った値では照合になりません。
bridge-maintainer namespaces="chatgpt-project-bridge-bundle" ssh-ed25519 AAAA...

Windows

署名がある場合（SHA256SUMS.txt.sig）:

cmd /c "ssh-keygen -Y verify -f allowed_signers -I bridge-maintainer -n chatgpt-project-bridge-bundle -s SHA256SUMS.txt.sig < SHA256SUMS.txt"

署名がない場合は指紋を比べます:

(Get-FileHash .\SHA256SUMS.txt -Algorithm SHA256).Hash.ToLower()

どちらの場合も、各ファイルを一覧と照合します:

Get-Content .\SHA256SUMS.txt | ForEach-Object { $hash, $name = $_ -split '\s+', 2; if ((Get-FileHash -LiteralPath $name -Algorithm SHA256).Hash.ToLower() -ne $hash) { throw "不一致: $name" } }; 'OK'

Ubuntu

署名がある場合（SHA256SUMS.txt.sig）:

ssh-keygen -Y verify -f allowed_signers -I bridge-maintainer \
  -n chatgpt-project-bridge-bundle -s SHA256SUMS.txt.sig < SHA256SUMS.txt

署名がない場合は指紋を比べます:

sha256sum SHA256SUMS.txt

どちらの場合も、各ファイルを一覧と照合します:

sha256sum -c SHA256SUMS.txt

インストーラーは最初に「署名または指紋の照合は済みましたか」と確認します。照合済みで確認を省く場合は -Verified／--verified を付けます。

Windows 4. Windowsへインストール

Windows Bundleをコピーして照合する

install.ps1、Skill ZIP、SHA256SUMS.txt、VERSION.txt（署名した場合は SHA256SUMS.txt.sig も）を同じフォルダーに保ち、3. 実行前の照合を行います。

Windows PowerShell 5.1から1コマンドで導入する

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1

依存物を取得する前にSkill ZIPを照合し、ZIP内の dependencies.lock.json を読みます。不足時だけPowerShell 7とGitを正確なwinget IDで、Node.js LTSはロックで固定した版で導入します。Tunnel Clientはロックで固定した版だけを取得し、固定したSHA-256と必須CLI flagを検証します。管理画面（GUI）用のランチャー chatgpt-project-bridge-gui と、スタートメニューのショートカット「ChatGPT Project Bridge」も作ります。

プロジェクトを承認付きで追加する

chatgpt-project-add `
  -ProjectRoot 'E:\work\MyProject' `
  -ProjectName 'MyProject' `
  -TunnelId 'tunnel_0123456789abcdef0123456789abcdef'

scaffoldと自己試験の後、公開範囲（ファイル、ディレクトリ、拒否ディレクトリ、Gitの公開設定）と指紋を表示し、承認後にだけprofile設定へ進みます。承認は %APPDATA%\chatgpt-project-bridge\approvals に保存されます。設定成功後にRuntime API Keyを非表示入力し、Doctorを実行します。

Windowsの鍵：同じWindowsユーザーだけが復号できるDPAPI暗号文です。既存keyは内容を読まず存在だけで再利用し、交換時だけ-ReplaceKeyを指定します。

Ubuntu / WSL 5. Ubuntuへインストール

Ubuntu Bundleをコピーして照合する

install.sh、Skill tar.gz、SHA256SUMS.txt、VERSION.txt（署名した場合は SHA256SUMS.txt.sig も）を同じフォルダーに保ち、3. 実行前の照合を行います。

1コマンドで導入する

bash ./install.sh

Ubuntu LTS 22.04 / 24.04 / 26.04のamd64・arm64に対応します。不足apt packageだけを導入し、既存Node.js 18以上は維持します。無い場合とTunnel Clientは、tar.gz内の dependencies.lock.json で固定した版だけを取得し、固定したSHA-256を照合します。curlはHTTPS以外への接続とリダイレクトを拒否します。PATHは管理marker付きで~/.profileへ重複なく設定します。管理画面（GUI）用のランチャー chatgpt-project-bridge-gui とアプリメニューの項目も作りますが、GUIに必要な python3-gi と gir1.2-gtk-3.0 は自動では入れません（不足していれば警告だけを出します）。インストーラーの中のPythonは python3 -I で動かし、実行したフォルダー（Bundleフォルダー）に置かれた偽のモジュールを読みません。アプリメニューの項目（.desktop）は、置き場かエントリがsymlinkのときは作らず、警告を出して続けます。相対パスの XDG_DATA_HOME は無視します。

プロジェクトを承認付きで追加する

chatgpt-project-add \
  --project-root "$HOME/work/MyProject" \
  --project-name MyProject \
  --tunnel-id tunnel_0123456789abcdef0123456789abcdef

同じTunnel/profileは再利用し、別rootまたは別Tunnelはkey入力より前に拒否します。公開範囲の承認は ~/.config/chatgpt-project-bridge/approvals/（0600）に保存されます。

Ubuntuの鍵：~/.config/tunnel-client/secrets/以下へmode 0600で保存され、YAMLにはfile:/path参照だけが入ります。暗号化されないため別PCへコピーしません。

WSLを使う場合

  • Windowsパスではなく、Ubuntuから見える`/home/...`または`/mnt/c/...`を指定します。
  • `tunnel-client`もNode.jsもWSL内のLinux版を使います。
  • `Start`を実行したWSL端末を閉じるとTunnelも停止します。

7. 毎日の使い方

Start／start は起動前に公開範囲の承認を確認します。.chatgpt-project-bridge.json が変わっていれば、変更点を表示して承認を求めます。承認されるまで、ChatGPTからのツール呼び出しはすべて拒否されます。

Windows

chatgpt-project-bridge -Action Update -ProjectRoot 'E:\work\MyProject'
chatgpt-project-bridge -Action Start  -ProjectRoot 'E:\work\MyProject'

Ubuntu

chatgpt-project-bridge update --project-root "$HOME/work/MyProject"
chatgpt-project-bridge start  --project-root "$HOME/work/MyProject"

ChatGPTの新しいチャットでAppを選択し、次のように依頼します。

MyProjectの接続を使って、get_project_context と get_project_status を実行してください。
取得した文書の更新日時、現在のGitブランチ、現在状態を要約してください。
ツールを呼べなかった場合は推測せず、その理由を教えてください。

共通 7-2. 複数プロジェクトを1つにまとめる（ハブ方式）

同じPCの複数プロジェクトを、PCごとに1つの Tunnel・ChatGPT App・Runtime API Key で公開できます。プロジェクトが増えても、作り足す必要はありません。

Windows

chatgpt-hub-add -ProjectRoot 'E:\work\ProjectA' -TunnelId 'tunnel_...'
chatgpt-hub-add -ProjectRoot 'E:\work\ProjectB'

Ubuntu

chatgpt-hub-add --project-root "$HOME/work/ProjectA" --tunnel-id tunnel_...
chatgpt-hub-add --project-root "$HOME/work/ProjectB"
  • 1つ目: 公開範囲の承認 → ハブへ登録 → Tunnel ID → プロファイル生成 → Runtime API Key → doctor → 起動。このPC用に Tunnel・キー・App を1つずつ作る。
  • 2つ目以降: 公開範囲の承認 → ハブへ登録だけ。Tunnel・キー・App には触れず、起動中のハブに再起動なしで反映される。
  • ChatGPT では最初に list_projects を呼び、各ツールの project 引数でプロジェクトを指定する。
  • 管理: HubList／hub-list、HubStart／hub-start、HubStop／hub-stop、HubRestart／hub-restart、HubDoctor、HubStatus、HubRemove -HubName 名前。どれも chatgpt-project-bridge に続けて指定する（例: chatgpt-project-bridge hub-start）。
  • ChatGPT がプロジェクトを読む時点で、ハブが起動している必要がある。プラグインの作成も、ハブの起動中に行う。
  • 自動起動（任意）: HubServiceInstall／hub-service-install で、サインイン時にハブを起動する。解除は HubServiceUninstall／hub-service-uninstall。未承認のプロジェクトは公開しないまま起動する。Windows はサインイン時に起動するため、自動サインインを設定していなければ、再起動後に人がサインインするまで起動しない。Ubuntu は linger も有効にするので、ログインしていないときも起動して公開が続く。登録の状態は HubStatus・HubDoctor／hub-doctor とインストーラーが表示する（自動では登録しない）。
  • 通知: ハブの起動時と、ChatGPT からのアクセス時にデスクトップ通知を出す（同じプロジェクトは60秒に1回まで）。すべてのアクセスは access.log（Windows は %APPDATA%\chatgpt-project-bridge、Ubuntu は ~/.local/state/chatgpt-project-bridge）に記録する。
制約：1つの Tunnel ID で同時に動かせる Tunnel Client は1台だけです（OpenAI の tunnel-client README に明記）。複数PCで同じ Tunnel を同時に使わず、PCごとにハブを作ってください。
注意：App を使えるチャットからは、承認済みの全プロジェクトが読めます。ある文書に紛れた指示で、別プロジェクトを読むよう誘導されることがあります。機密度の違うプロジェクトは、従来方式（chatgpt-project-add）で別の Tunnel・App に分けてください。ハブを止めると全プロジェクトが止まります。同じプロジェクトをハブ方式と従来方式で同時に起動しないでください。

共通 7-3. 管理画面（GUI）で操作する

コマンドを覚えなくても、全ての操作を画面から実行できます。ボタンや入力欄にマウスを載せると、何をするか・いつ使うか・注意点が日本語で出ます。画面は既存のコマンドを呼ぶだけで、承認・キー・上書きの安全確認は変わりません。

Windows

スタートメニューの「ChatGPT Project Bridge」、または次のコマンドで開きます。

chatgpt-project-bridge-gui

PowerShell 7 と WinForms を使います。Windows 版の画面は、実機での確認が済むまで未検証です（手順は references/gui-windows-check.md）。

Ubuntu

アプリメニューの「ChatGPT Project Bridge 管理画面」、または次のコマンドで開きます。

chatgpt-project-bridge-gui

初回だけ、次のパッケージが必要です。インストーラーは自動では入れません。

sudo apt install python3-gi gir1.2-gtk-3.0

プロジェクトを追加する

「かんたん」タブで「プロジェクトのフォルダー」を指定し、「プロジェクトを追加」を押します。設定ファイルがまだ無いときは「プロジェクト名」も入力します。「Tunnel ID」（ハブに記録済みのもの）と「Tunnel Client の場所」は、分かっていれば起動時に入っています（入力済みの値は書き換えません）。足場（設定ファイルと文書 2 つ）は、無ければ自動で作られます。

公開範囲を読んで承認する

確認ダイアログは、上から次の順に並びます。固定の見出し（承認状態・プロジェクトルート・プロファイル・ハブの警告）、スクロールする詳細（1項目1行・番号つき・引用符つき・全件）、固定の要約（件数・Gitの公開の有無・指紋64桁）、「内容を読みました」、「この内容で承認」です。「内容を読みました」は、詳細を末尾までスクロールするとチェックできます（全部収まる短い内容なら最初から）。チェックするまで「この内容で承認」は押せず、既定のボタンは「キャンセル」です。承認しなければ何も実行されず、そのプロジェクトは公開されません。

キーは別の端末窓に入力する

別の端末窓（Windows は別のコンソール窓）が開き、コマンドが自動で実行されます。Runtime API Key を求められたら、その窓に貼り付けます。画面には入力しません。窓はコマンドを1回だけ実行し、終了コードを表示してEnterキーを待ちます（対話のプロンプトは残りません）。結果を読んでEnterキーで閉じ、「一覧を更新」を押します。

ハブを起動する

「ハブを起動」を押します。未承認のプロジェクトがあれば、起動の前に承認ダイアログが出ます。起動すると、画面の上部の「ハブ」の表示が ハブ: ● 実行中（PID …） になります（3 秒ごとに調べます。示すのは Tunnel Client のプロセスの有無だけで、この画面の外で起動したハブも表示します）。ChatGPT から読ませている間は、画面を開いたままにします（画面を閉じると、画面から起動したハブは止まります）。強制終了（SIGKILL）や画面のクラッシュでは止まらず、ハブが残ることがあります。そのときは画面を開き直し、上部の「ハブ」の表示か「ハブの稼働状態」で確かめて、残っていれば「ハブを停止」を押します。

承認：表示された公開範囲を読まずに承認しないでください。画面が指紋をコマンドへ渡すのは、チェックして「この内容で承認」を押したときだけです。
「承認できません」（赤字）：設定に制御文字・行区切り・双方向制御文字・不可視文字があると、赤字で理由と該当項目が出て、承認ボタンは常に押せません（公開範囲の確認の段階でサーバーが拒否し、ログにメッセージが出る場合もあります）。偽装の可能性があります。ファイルやフォルダーの名前を直してから、やり直します。
別のフォルダーの承認を上書きするとき：同じプロファイル名で別のフォルダーが承認済みだと、赤字の警告と、追加のチェックが出ます。取り違えや設定の偽装でないかを確かめてから承認します。
他人から受け取ったプロジェクト：承認ダイアログを最後まで読み、赤字の警告が出たら承認しません。.git ごと配られたものを疑ってください。.git/config に実行を伴いうる設定があると、Gitの情報（ブランチ・変更の件数・コミット件名）の取得だけが止まります。
上書き系：「上書きを許可（force）」「プロファイルを作り直す」「キーを置き換える」は既定でオフです。オンにするたびに確認が出ます。
成功表示：画面の「CLI の処理は成功しました」は、コマンドの終了コードが 0 だったことだけを表します。ChatGPT 側の確認（Tool Scan と End-to-End）は別の段階です（10. 「接続完了」の判定）。

8. 別PC・別プロジェクトへ移す

対象コピーするコピーしない／再設定する
スキルExportBundleで作った対象OSフォルダーarchiveだけを抜き出さずinstall、SHA256SUMS.txt、VERSION.txt、署名も一緒にコピー。指紋と公開鍵は別経路で伝える
プロジェクト`.chatgpt-project-bridge.json`、Context、Status絶対パスとhealth portは`ConfigureTunnel`で再生成
公開範囲の承認コピーしない移行先PCで表示内容を確認して承認し直す
API Keyコピーしない移行先PCで`SaveKey`／`save-key`を再実行
Tunnel旧PCを停止して置換する場合だけ同じ`tunnel_id`を利用可能2台同時稼働、または別プロジェクトは別Tunnel推奨

Windowsから両OS Bundleを作る

chatgpt-project-bridge -Action ExportBundle `
  -OutputPath 'D:\Transfer\ChatGPT' -Force `
  -SigningKey "$env:USERPROFILE\.ssh\id_ed25519"

Ubuntuから両OS Bundleを作る

chatgpt-project-bridge export-bundle \
  --output-path "$HOME/Transfer/ChatGPT" --force \
  --signing-key "$HOME/.ssh/id_ed25519"

SHA256SUMS.txt にはarchive、installer、VERSION.txt が入ります。署名鍵を指定すると SHA256SUMS.txt.sig を作り、最後に各OSの指紋を表示します。

依存物の版を上げるとき（保守者）：Skillのソース上で UpdateLock／update-lock を実行し、表示された版とSHA-256の差分を確認してからBundleを作り直します。導入先は「最新版」を取りに行きません。Tunnel Clientは、リリースに付いているSLSA来歴証明を GitHub CLI（gh attestation verify）で検証し、openai/tunnel-client の release.yml がそのタグとコミットからビルドしたと確認できた版だけを固定します。保守者のPCに gh が必要です（導入先には不要）。Node.jsはwingetに登録済みの版を選びます。
2.0.0からの移行：2.0.0で作ったTunnel profileは承認ファイルを渡さないため拒否されます。プロジェクトごとに一度だけ、同じTunnel IDで chatgpt-project-add に -ForceReconfigure／--force-reconfigure を付けて実行し、profileを再生成して承認してください。
後方互換：単一ZIPまたはtar.gzだけが必要な場合はExportSkill／export-skillを引き続き利用できます。

9. 公開範囲と鍵の安全確認

  • 既定公開は`CHATGPT_PROJECT_CONTEXT.md`、`CHATGPT_PROJECT_STATUS.md`、ルート`README.md`だけ。
  • `.git`、`.codex`、`.claude`、`Prompts`、`Documents`、`Saved`、build出力は既定で拒否。
  • 公開範囲の承認はプロジェクトの外に保存され、設定が変わると承認し直すまで全ツールが拒否される。
  • Gitのファイル名とコミット件名は既定で非公開（`gitExposure.paths`／`gitExposure.commitSubjects` が `false`）。有効にしても拒否ディレクトリ配下と機微な名前は返さない。
  • `.env*`、`*.pem`、`*.key`、`id_rsa*`、名前に`credential`／`secret`を含むもの、`.git`／`.ssh`／`.aws`などの配下、バイナリは、許可リストに入れても公開しない。
  • 公開文書内の秘密鍵ブロック、トークン、JWT、URL内のパスワード、`password: …`の値は伏せ字にする（最後の防御）。
  • API Keyをプロジェクト、Git、YAML、コマンド引数、チャットへ貼らない。
  • Ubuntuでは文書を読むたびに、外部symlink、hardlink、プロジェクト内の別mount境界を拒否。
  • 設定の項目やフォルダーのパスに制御文字・行区切り・双方向制御文字・不可視文字（ZWNJなどの書式文字を含む）があると、設定全体を拒否する（サーバー・コマンド・画面とも）。パスは、区切りごとの末尾の . と空白、:（Windowsは8.3短縮名も）も拒否する。
  • プロジェクトの .git/config（local・worktree）に、実行を伴いうる設定（core.fsmonitor、core.hooksPath、filter.* のコマンドなど）があると、Gitの情報だけを取得しない（文書の公開は続く）。Git LFS の標準の設定値は例外。
  • MCPサーバーは、承認ファイルが、symlink・自分の所有でない・group/otherに書き込み権がある場合や、その置き場所のディレクトリが同じ状態のときは、未承認として扱う（Windowsは symlink の拒否だけで、ACLは検査しない）。
  • 許可ディレクトリを追加するときは、ChatGPTへ見せてよいMarkdownだけが入っていることを確認。
禁止：公開範囲を簡単に広げる目的でプロジェクト全体やソースツリーを許可しないでください。表示された公開範囲を読まずに承認したり、-ExposureSha256／--exposure-sha256 で承認を自動化したりしないでください。設定変更後は必ず`Test`／`test`を再実行します。
限界：承認ファイルは、同じユーザー権限で動いているソフトウェアによる書き換えまでは防げません。
